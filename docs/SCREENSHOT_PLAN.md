## Capture checklist

- Use real application output and coherent demo-only records.
- Capture both wide and one mobile-width screen for responsive evidence.
- Avoid browser extensions, notifications, API keys, terminal windows, email addresses, or local filesystem paths.
- Use English for the primary set; optionally add one Italian view to demonstrate localization.
- Use one theme consistently for the main set and one secondary capture to demonstrate the alternate theme.
- Verify filenames, crop, readability, and absence of sensitive data before committing.
- Store approved images in `docs/screenshots/`; update the README to embed only files that actually exist.
